# The forecast on Home Compute (a Mac mini)

The worker image runs on this Mac through [Home Compute](https://github.com/sprintengine/home-compute)
and Bacalhau, on `deploy/local/jobs.toml`'s timetable, and publishes each run to the
R2 bucket. Visitors only ever read the bucket, so the site keeps serving the last
forecasts if the Mac is off; it just stops updating.

```text
launchd ─┬─ dev.sprintengine.bacalhau      bacalhau serve (orchestrator + compute), Colima's Docker
         └─ dev.sprintengine.home-compute  home-compute daemon: submits each job on its UTC slots,
                                           API on 127.0.0.1:4786 for the menu bar app
```

## Files

| File | What it is |
| --- | --- |
| `home-compute.json` | Generated by `deploy/schedules.py` from `deploy/local/jobs.toml`. Edit the TOML, then rerun the script. |
| `.env` | Private (git-ignored): the image, the R2 bucket and key, `FORCE5_SIDECARS=0`, the API token. `setup` writes it from `r2.env`. |
| `state/` | The controller's state (git-ignored). |
| `macmini.sh` | Setup and control, from the terminal or the Home Compute Bar app. |
| `panel.py` | The app's JSON answers: service state, `.env` settings, the R2 check, token rotation, image freshness. |

## From the menu bar

Home Compute Bar (`../home-compute/macos`, `./build-app.sh --install`) runs this
script for you: its window sets up and starts the services, edits the R2 settings
and tests the bucket, rebuilds the image when the code has moved on, and edits the
timetable. A timetable edit is written to `deploy/local/jobs.toml` (comments kept)
and regenerated for Home Compute and Cloudflare by `deploy/schedules.py --set`;
restart the scheduler to apply it, as for an `.env` change.

## Run it

Needs Colima, Node 22+, the Bacalhau CLI in `~/.local/bin` and a `../home-compute` checkout.

```sh
deploy/home-compute/macmini.sh setup     # image, .env, token, launch agents; starts nothing
deploy/home-compute/macmini.sh start     # both services; they also start at login from now on
deploy/home-compute/macmini.sh status    # each job: next slot, last outcome, run published
deploy/home-compute/macmini.sh run harmonie   # one job now
deploy/home-compute/macmini.sh logs
deploy/home-compute/macmini.sh stop
```

After changing the importer code, `macmini.sh image` rebuilds `wingfoil-forecast:local`;
the next submission uses it. No registry is involved: Bacalhau runs the local image.

Colima has to be running for any job to start. `start` starts it if it is not, but
after a reboot it only comes back by itself with `brew services start colima`.

## What a slot costs

Every forecast importer except tides and sea temperature first reads the run the
bucket already serves and exits at once if its source has nothing newer
(`readsPublishedRun` in `force5/ingest/registry.py`), so the hourly ECMWF check or a
Météo-France slot that finds the previous cycle costs a listing, not an import.

Bacalhau is told the Colima VM's size (4 CPUs, 5.5 GB of its 6 GiB), and each job's
memory is a hard ceiling: 4 GB for a model, 1-2 GB for the station feeds. So one
large import runs at a time and the rest queue for up to an hour. Give Colima more
memory (`colima stop && colima start --memory 8`, then `macmini.sh setup` to
rewrite the agents) if queues grow long.
